1Overview
I wanted to assign you a task on LLMs that utilises cloud computing concepts. But as you
know, deploying LLMs on your low-end laptops is non-trivial. So you'll be using knowledge
distillation over a larger model, the teacher model (which is still not large enough, probably
2 to 4 B parameters), into an extremely small model (the student model, let's say 70 million
parameters). And then you will use this smaller model for the deployment. Yes, it will be quite
a useless model, but the quality is not our concern.
Knowledge distillation (KD) is a model-training technique in which a smaller student model
learns to reproduce the outputs or behaviour of a more capable teacher model. The objective is
while reducing the resources required for inference.
So dig a little deeper on your own first and explore how KD works. How can you apply KD
practically? I have put some links in the subsequent sections for kickstarting, but do not limit
yourself to these only.
You'll be using AI and no one can stop you. But do use it with your eyes wide open.
In this project, you will apply sequence-level knowledge distillation to a command-parsing
task. You will first run a teacher model to generate responses for a collection of natural-
language commands. You will then use these responses as training targets to fine-tune a smaller
language model, and then deploy the resulting model as a service on a local Kubernetes-based
cloud environment.

4 Application Description
You are building a small command parser, the kind of thing that sits inside a voice assistant. It
takes one short English command and returns a JSON object that says what the user wants
(the intent) and the key details (the slots). For example:
Input
set an alarm for seven thirty am tomorrow
Output
{"intent":"alarm_set", "date": "tomorrow","time": "seven thirty am","place": null}
Every output is one JSON object with exactly four keys: intent, date, time, and place.
Nothing more, nothing less.
The intent is one of these eight:
Intent
Meaning and an example command
alarm_set
Create an alarm:set my alarm for siz am tomorrow
alarm_query
Ask about existing alarms: what alarms do i have set for today
calendar_set
Add an event or reminder:add running to my calendar for thursday
calendar_query
Ask about scheduled events:what are my plans for the month of may
calendar_remove
Delete an event: delete my appointment tomorrow
weather_query
Ask about theweather:what is theweatherinlondon
datetime_query
Ask the date or the time: what time is it in tokyo
recommendation_events
Ask for events to attend:what events are happening in los angeles
The three slots follow three simple rules:
1. Copy the value exactly as it appears in the command. Do not convert it. seven am stays
seven am; it does not become 07:00.
2. Copy the shortest phrase that carries the meaning, without words like at, on, in, or for.
3. If the command does not mention a slot, it is null. Never invent a value.
One more example: what is the weather in london gives {"intent": "weather_query",
